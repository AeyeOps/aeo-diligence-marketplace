# AWS Inspector adapter

Optional and full tier only. `code_diligence.security.inspector` reads active Inspector findings through boto3 with the profile and region in `sources.aws_inspector`. The target's `fix_available` list selects any of the provider's `YES`, `NO`, and `PARTIAL` values; an empty or omitted list applies no fix-availability filter. It also loads saved snapshots from `snapshot_dirs`: JSON files named `account-findings-<YYYYmmddTHHMMSSZ>.json` with `severities` (the severities that read covered) and `findings` (Inspector's own finding objects). The same target selections apply to snapshots. Snapshots already recorded are skipped by their read time.

A finding is in scope when a resource's id, ECR repository name, Lambda function name or `Name` tag starts with a `resource_prefixes` entry; an empty list keeps every resource. Each read becomes one `security_reads` row, including its resource scope and fix-availability selection, and one `security_observations` row per qualifying finding, keyed by the finding id at the end of its ARN. Changing either selection replaces the target's previous read history using the existing collection behavior; histories with different populations are not combined.

`security_monthly` covers the last six calendar months in `timezone`, per severity, using only reads that covered that severity. Opening is the set at the last covering read before the month, or at the month's first read when coverage starts inside it (`opening_from_first_read`). Newly seen is every finding observed during the month that was not in the opening set. Resolved or retired is every finding in the opening set or observed during the month that is absent from the month's last read. Open at end is the last read's set, so opening plus newly seen minus resolved equals open at end. A finding that leaves and returns within a month counts once. The monthly table remains a six-month cache. The Security findings chart recomputes additions, removals and backlog from the raw reads for its requested interval and range, using the same set calculation in `security/periods.py`. It does not sum cached month totals into quarters or years. See the `aeo-diligence-dashboard` skill's `references/security-chart.md`.

Inspector deletes closed findings after 30 days and findings on deleted resources after 3, so history depends on saved snapshots and earlier reads. Counts are findings on resources, not unique CVEs; a resolution can be a patch or a retired resource. Missing credentials, an unknown profile or denied access are recorded as an `aws-inspector` tool failure.
